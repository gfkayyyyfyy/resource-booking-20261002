================================================================================
resource-list 时段可预约筛选流程说明（--start / --end）
================================================================================

本文描述带 --start 与 --end 的资源目录查询（resource-list）从命令行输入
到 JSON 输出的完整流程，全部结论均可对照源码核实。涉及文件只有两个：

  booking/__main__.py   命令行入口、参数解析与校验、错误输出
  booking/store.py      SQLite 持久化层、目录读取与时段筛选

时段筛选是 resource-list 在既有 --contains 名称片段筛选之外的可选条件：
--start/--end 两个都省略时不做时段筛选，完整保留原目录行为；--contains 的
既有语义也完全不变。本文只描述既有行为，不改动任何产品代码、公开命令、
输出协议、既有测试、README 或数据库格式；其他入口（resource-add、
reserve、cancel、reschedule、day-query、free-query）的行为均不在本文范围，
保持不变。

--------------------------------------------------------------------------------
1. 总体流程概览
--------------------------------------------------------------------------------

一次带时段的 resource-list 依次经过四个阶段，顺序固定：

  (1) 参数解析与输入校验   booking/__main__.py: main() 的 resource-list
                           分支（booking/__main__.py:301-318）
  (2) 打开数据库           booking/store.py: connect()
  (3) 目录读取与筛选       booking/store.py: list_resources(conn,
                           contains, window)
  (4) 结果输出             booking/__main__.py: main() 的 resource-list
                           分发（booking/__main__.py:368-371），经由 _emit()

关键次序：阶段 (1) 的任何失败都在阶段 (2) 之前返回，因此非法输入不会创建
数据库文件、不会迁移旧库、不会改动任何记录。这一点由 main() 的结构保证
——全部校验放在 try 块内、connect 之前（booking/__main__.py:275-345）：

    # 先解析参数并完成全部输入校验，之后才连接/初始化数据库，
    # 保证非法输入不会新建文件或改动任何记录。
    try:
        args = parser.parse_args(argv)
        ...
    except UsageError:
        return invalid_input()

    # 输入合法后再打开数据库（不存在则初始化），后续进程沿用同一文件。
    conn = store.connect(args.db)

时段筛选的核心结论：返回的每一个资源，在整个查询窗口 [start, end) 内都
可预约——该资源在库中不存在任何与窗口“有正时长交集”的未取消预约。同一
资源上只要存在一条这样的预约，该资源就被整体排除；端点相接不算正时长
交集，不阻挡；已取消记录不占用；不同资源各自独立判断；跨日区间与重复
预约都按预约的完整起止时间文本比较。

--------------------------------------------------------------------------------
2. 阶段一：参数解析与输入校验
--------------------------------------------------------------------------------

2.1 命令行形状

resource-list 接受三个可选参数（booking/__main__.py:238-244）：

    p_list = subparsers.add_parser("resource-list")
    # 可选：只返回保存后的名称包含该片段的资源；缺省返回完整目录。
    p_list.add_argument("--contains", default=None)
    # 可选且必须成对出现：只返回 [start, end) 内没有任何未取消预约
    # 相交的资源；两个都省略时不做时段筛选，保留原目录行为。
    p_list.add_argument("--start", default=None)
    p_list.add_argument("--end", default=None)

  - --db 为全局必填参数（booking/__main__.py:215），值为 SQLite 文件路径。
  - --start/--end 省略时 argparse 给出默认值 None。二者是“必须成对”的
    一组：要么都省略，要么都给值。
  - argparse 本身的报错（缺少 --db、未知子命令、未知参数、--start/--end
    缺值等）被自定义解析器 _Parser.error 转成 UsageError
    （booking/__main__.py:56-60），与值校验失败走同一路径，因此 argparse
    不会自己向 stderr 输出用法文本。

2.2 成对校验与窗口解析（booking/__main__.py:301-318）

main() 的 resource-list 分支先处理 --contains（沿用既有规则，见 2.4），
再处理时段：

    window = None
    if (args.start is None) != (args.end is None):
        raise UsageError("--start and --end must be given together")
    if args.start is not None:
        window = parse_time_window(args.start, args.end)

  - 两个都省略：异或为假、args.start is None，局部变量 window 保持 None，
    阶段三不做时段筛选，返回原目录。
  - 只给一端（命令行上出现 --start X 但没有 --end，或只有 --end X）：
    异或为真，立即抛 UsageError，此时不会解析另一端。
  - 写了 --start/--end 却不给值（末尾只写 --start，或 --start X --end）
    属于 argparse 层面的缺值报错，同样经 _Parser.error 转为 UsageError，
    见 2.5。
  - 两个都给：调用 parse_time_window() 完成与 reserve/free-query/
    reschedule 完全相同的时间窗口校验。校验通过时 window 是 (start, end)
    原始定宽文本对（parse_time_window 返回入参原文，
    booking/__main__.py:153-167），原样交给存储层。

2.3 时间窗口规则：parse_time / parse_time_window

parse_time_window（booking/__main__.py:153-167）先严格解析开始、再严格
解析结束，然后要求开始严格早于结束：

    start_dt = parse_time(start_text)
    end_dt = parse_time(end_text)
    if not start_dt < end_dt:
        raise UsageError("start must be strictly before end")

parse_time（booking/__main__.py:142-150）的规则：

  - 必须完整匹配 TIME_RE = ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}$
    （booking/__main__.py:22）：定宽、零填充的 YYYY-MM-DDTHH:mm。
  - 数字位只接受 ASCII [0-9]，刻意不用 \d：\d 会匹配全角、阿拉伯文等
    各语种十进制数字，而 strptime 也接受它们，会让
    "２０２６-10-05T09:00"、"2026-10-05T09:0０" 之类文本绕过校验
    （booking/__main__.py:18-22 注释说明）。
  - 通过正则后再用 strptime 解析，非法日期（如 2026-02-30）抛 ValueError
    并被转成 UsageError。
  - 拒绝秒（2026-10-05T09:00:00）、时区后缀（...+08:00、...Z）、未零
    填充（2026-10-5T9:00）、错误分隔符（2026/10/05T09:00、空格代替 T）、
    首尾空白（" 2026-..."、"...\t"，不做 strip）。
  - 成功时返回带固定时区 UTC+08:00 的 datetime
    （TIMEZONE_OFFSET，booking/__main__.py:16）。所有输入时间统一按
    UTC+08:00 解释，与运行机器的时区无关。
  - 开始必须严格早于结束：相等（10:00/10:00）或颠倒（11:00/10:00）都抛
    UsageError。允许过去日期，也允许跨午夜/跨日窗口——这些在
    parse_time_window 中不受限制（booking/__main__.py:159-161 注释）。

2.4 --contains 名称片段：既有语义不变

--start/--end 不改变 --contains 的任何既有规则
（booking/__main__.py:302-308）：省略时 contains 为 None 不筛选；给出时
先 strip 首尾空白（中间空格保留），strip 后为空（空文本或纯空白）抛
UsageError。匹配发生在存储层 Python 侧（见 4.3）。两个筛选器同用时取
交集：名称命中且窗口内可预约的资源才返回。

2.5 校验失败的统一出口

下列情况全部抛 UsageError 并被同一处 except 捕获
（booking/__main__.py:344-345），由 invalid_input()
（booking/__main__.py:68-69）向标准输出打印且只打印：

    {"error": "invalid_input"}

退出码 2，标准错误为空（没有任何文本，也没有异常堆栈）。包括：

  - 只提供 --start 或只提供 --end（端点不成对）；
  - --start 或 --end 缺少值（如末尾只写 --start、--start X --end）：
    argparse 报错，经 _Parser.error 转为 UsageError；
  - 非法日期（如 2026-02-30T09:00）；
  - 格式不符（带秒、时区后缀、未零填充、错误分隔符、首尾空白等）；
  - 非 ASCII 时间数字（全角、阿拉伯文数字，含与 ASCII 混写）；
  - 开始不早于结束（起止相等或开始晚于结束）；
  - --contains 缺值、空文本、纯空白（既有规则）；
  - resource-list 不支持的参数、缺少必填的 --db 等：argparse 拒绝。

以上各类情况不区分错误文案，输出完全相同；且都在 store.connect 之前
返回：不创建数据库文件、不触发旧库迁移、不触碰任何数据（见第 3 节）。

--------------------------------------------------------------------------------
3. 阶段二：打开数据库 store.connect（booking/store.py:22-39）
--------------------------------------------------------------------------------

只有输入全部合法后才调用 store.connect(args.db)
（booking/__main__.py:348）：

  - 文件不存在时，sqlite3.connect 创建该文件并执行 SCHEMA
    （booking/store.py:6-19，CREATE TABLE IF NOT EXISTS resources /
    bookings）。因此对一个不存在的路径执行合法的带时段 resource-list，
    返回空数组的同时会在磁盘上留下初始化后的数据库文件。
  - 对取消功能上线前创建的旧库，connect 用 PRAGMA table_info(bookings)
    检查列；缺少 cancelled 列时 ALTER TABLE 补齐，已有预约一律视为未
    取消（默认值 0），不重建数据（booking/store.py:34-38）。这条迁移是
    所有命令共用的连接逻辑，带时段查询打开旧库时同样沿用。
  - 连接置于 autocommit 模式并启用外键。

“只读”的准确含义需要区分两类写：

  - 业务数据层面，带时段查询确实只读：list_resources 只执行一条 SELECT
    （见第 4 节），不开始事务、不 INSERT/UPDATE/DELETE，不新增或删除
    资源与预约，也不消耗 AUTOINCREMENT 标识（查询后再登记资源/预约，新
    标识仍紧接原有最大标识）。
  - 文件层面，打开数据库这一步本身可能写文件：不存在的路径会被初始化，
    缺少 cancelled 列的旧库会被补齐。因此“查询只读”的准确承诺是“合法
    查询不改变业务记录，但沿用既有的建库与旧库迁移行为”，不是“绝不写
    文件”。

--------------------------------------------------------------------------------
4. 阶段三：目录读取与时段筛选 list_resources（booking/store.py:55-95）
--------------------------------------------------------------------------------

4.1 分支：window 是否为 None

    if window is None:
        rows = conn.execute(
            "SELECT id, name FROM resources ORDER BY id ASC"
        ).fetchall()
    else:
        start, end = window
        rows = conn.execute(
            """
            SELECT id, name FROM resources
            WHERE NOT EXISTS (
                SELECT 1 FROM bookings
                WHERE bookings.resource_id = resources.id
                  AND cancelled = 0
                  AND start < ? AND end > ?
            )
            ORDER BY id ASC
            """,
            (end, start),
        ).fetchall()

window is None（两端都省略）走第一条 SELECT，与时段筛选上线前完全相同，
预约表不参与（对应 RESOURCE_DIRECTORY_FLOW.txt 描述的原目录行为）。

4.2 时段判定：NOT EXISTS 与左闭右开的正时长交集

window 给出时，对 resources 表每一行做一次相关子查询：仅当 bookings 表中
“不存在”满足全部四个条件的行时，该资源才入选——

    bookings.resource_id = resources.id   只看同一资源的预约
    AND cancelled = 0                     只看未取消预约
    AND start < :window_end               预约开始严格早于查询结束
    AND end   > :window_start             预约结束严格晚于查询开始

（参数按位置绑定为 (end, start)：第一个 ? 是窗口结束，第二个 ? 是窗口
开始。）

判定含义（与预约写入路径的冲突规则 has_conflict 同一条相交规则，
booking/store.py:105-142；list_resources 的文档串在 store.py:66-71 明确
“与 has_conflict 同一条相交规则”）：

  - 整个窗口可预约才返回：任何一条同资源未取消预约与 [start, end) 有
    正时长交集，NOT EXISTS 即为假，资源被排除。资源一旦被排除，结果中
    完全没有该项（不是部分时段可用的概念）。
  - 左闭右开，端点相接不阻挡：预约 end 恰等于窗口 start（前一条预约
    正好在窗口开始时结束），或预约 start 恰等于窗口 end（后一条预约
    正好在窗口结束时开始），都不满足严格不等式，不排除资源。
  - 任何正时长交集都排除：前段部分重叠、后段部分重叠、预约包含窗口、
    预约被窗口包含、两者完全相同，均满足两个严格不等式，全部排除。
  - 已取消记录不占用：cancelled = 0 条件使已取消预约（cancelled = 1）
    永远不进子查询；把冲突时段的预约取消后，资源在该窗口重新可预约。
  - 不同资源独立判断：子查询按 bookings.resource_id = resources.id
    相关，一个资源上的预约不影响任何其他资源；同名资源也是各自一行、
    各自判断、分别返回。
  - 跨日按完整起止时间：start/end 是零填充的 YYYY-MM-DDTHH:mm 定宽
    文本，字典序即时间先后，比较使用完整日期时间而非“当日时分”，因此
    跨午夜预约（如 2026-10-05T23:30–2026-10-06T00:30）与跨午夜窗口
    正确相交；仅日期相同但时段不相交不会被误判。
  - 重复预约按完整起止时间逐行判断：--repeat-weeks 生成的每次发生在
    bookings 表中都是各自独立的普通行（见 store.insert_bookings 文档串，
    booking/store.py:323-336，“各条预约持久化为普通预约，不记录任何组
    标识”），任一次发生与窗口相交即排除该资源；不与任何发生相交的窗口
    仍可预约。
  - 没有任何预约的资源，NOT EXISTS 恒真，自然入选。

4.3 排序、名称片段与结果整形

两条 SQL 都以 ORDER BY id ASC 收尾：

  - id 是 INTEGER PRIMARY KEY AUTOINCREMENT（resources 表，SCHEMA，
    store.py:7-10），按数值升序：标识 2 排在 10 之前，而不是按文本
    "1","10","2"。
  - SQL 不去重：同名资源各自独立的行分别保留，时段判定也逐行独立。

SQL 取回行后在 Python 侧套用 --contains 谓词
（booking/store.py:91-95）：

    return [
        {"resource_id": row[0], "name": row[1]}
        for row in rows
        if contains is None or contains in row[1]
    ]

  - contains 为 None 时谓词恒真；非 None 时用 Python in 做区分大小写的
    连续子串匹配（%、_ 按普通字符，无通配、无正则、无字符归一化），
    语义与不带窗口时完全一致。
  - 同用时是交集：先由 SQL 的 NOT EXISTS 保证时段可预约，再由 Python
    谓词保证名称命中；两者都满足的行才保留。
  - 筛选不改变顺序（仍按标识数值升序）、不改名称文本、不合并多行。
  - 每行整形为只含两个键的对象：resource_id（整数）与 name（保存值
    原样）。没有任何行满足（目录为空、全部被占用，或名称无命中）时
    返回空列表 []，属于成功结果。

--------------------------------------------------------------------------------
5. 阶段四：结果输出
--------------------------------------------------------------------------------

main() 对 resource-list 的分发只有一行（booking/__main__.py:368-371）：

    if args.command == "resource-list":
        return _emit(
            {"resources": store.list_resources(conn, contains, window)}, 0
        )

_emit()（booking/__main__.py:63-65）用 json.dumps(..., ensure_ascii=False)
向标准输出打印恰好一个 JSON 对象并返回退出码。成功时：

  - 退出码 0，标准错误为空；
  - 顶层只有一个键 resources，值为数组；
  - 数组每项只有两个键：resource_id（整数）与 name（字符串，保存值
    原样返回）；
  - 按 resource_id 数值升序；同名资源分别保留为独立的项；
  - 无匹配（目录为空、窗口内无资源可预约、名称片段无命中，或其交集为
    空）时 resources 是空数组 []，仍是退出码 0。

连接在 finally 中关闭（booking/__main__.py:465-466），与业务结果无关。
整条命令是只读查询：重复执行、或由独立进程重开同一文件再查，结果相同。

--------------------------------------------------------------------------------
6. 完整示例（全新 demo.sqlite，两条预约、两次查询）
--------------------------------------------------------------------------------

以下命令在全新环境可完整复现：在不含 demo.sqlite 的目录中，依次登记两个
资源、各预约一次，再执行两次 resource-list。命令通过公开入口
python -m booking 调用；每条命令是独立进程，时间一律按固定 UTC+08:00
解释。下列输出已在当前源码上逐条实际运行核对。

6.1 准备数据：登记两个资源、各预约一次

    python -m booking --db demo.sqlite resource-add --name "一号会议室"
    预期标准输出（退出码 0，标准错误为空）：
    {"resource_id": 1, "name": "一号会议室"}

    python -m booking --db demo.sqlite resource-add --name "二号会议室"
    预期标准输出（退出码 0，标准错误为空）：
    {"resource_id": 2, "name": "二号会议室"}

    python -m booking --db demo.sqlite reserve --resource 1 \
        --start 2026-10-05T09:00 --end 2026-10-05T10:00
    预期标准输出（退出码 0，标准错误为空）：
    {"booking_id": 1, "resource_id": 1, "start": "2026-10-05T09:00", "end": "2026-10-05T10:00"}

    python -m booking --db demo.sqlite reserve --resource 2 \
        --start 2026-10-05T10:00 --end 2026-10-05T11:00
    预期标准输出（退出码 0，标准错误为空）：
    {"booking_id": 2, "resource_id": 2, "start": "2026-10-05T10:00", "end": "2026-10-05T11:00"}

全新库首批资源标识按 AUTOINCREMENT 依次为 1、2，两条预约标识依次为 1、2。
库中未取消占用为：

    资源 1（一号会议室）：2026-10-05 09:00–10:00
    资源 2（二号会议室）：2026-10-05 10:00–11:00

6.2 查询一：10:00–11:00，端点相接获准，只返回一号会议室

    python -m booking --db demo.sqlite resource-list \
        --start 2026-10-05T10:00 --end 2026-10-05T11:00

预期标准输出（退出码 0，标准错误为空；实际打印为单行，无多余空白）：

    {"resources": [{"resource_id": 1, "name": "一号会议室"}]}

逐个资源按 NOT EXISTS 子查询判断：

  - 资源 1 的预约是 09:00–10:00，查询窗口是 10:00–11:00。比较两条严格
    不等式：预约 start(09:00) < 窗口 end(11:00) 成立，但预约 end(10:00)
    > 窗口 start(10:00) 不成立（10:00 并不严格晚于 10:00）。相交时长为
    零——预约恰在窗口开始的那一刻结束，左闭右开下端点相接不算重叠。
    不存在相交的未取消预约，资源 1 入选。
  - 资源 2 的预约是 10:00–11:00，与窗口完全相同：start(10:00) <
    end(11:00) 且 end(11:00) > start(10:00) 都成立，正时长交集 60 分钟，
    资源 2 被排除。

  结果只含资源 1。

6.3 查询二：09:30–10:30，两个资源都有正时长交集，返回空数组

    python -m booking --db demo.sqlite resource-list \
        --start 2026-10-05T09:30 --end 2026-10-05T10:30

预期标准输出（退出码 0，标准错误为空）：

    {"resources": []}

  - 资源 1 的 09:00–10:00 与 09:30–10:30 部分重叠：09:00 < 10:30 且
    10:00 > 09:30，交集 09:30–10:00 为 30 分钟正时长，排除资源 1。
  - 资源 2 的 10:00–11:00 与该窗口同样部分重叠：10:00 < 10:30 且
    11:00 > 09:30，交集 10:00–10:30 为 30 分钟正时长，排除资源 2。
    注意这里是“预约开始落在窗口内”，与 6.2 的端点相接不同：10:00 严格
    早于窗口结束 10:30，故不能获准。

  两个资源都被排除，交集结果为空，返回空数组（成功结果，退出码 0）。

6.4 重开同一文件结果相同

时段查询只读业务记录，不依赖进程状态。重新执行（或新进程重开
demo.sqlite）同样两条查询，输出与 6.2、6.3 完全一致；预约与资源标识也
不因查询而增加或改变。所有时间都按固定 UTC+08:00 解释，更换运行机器的
时区不影响上述结果。

旧库迁移（connect 的共用行为，本文第 3 节）：
  - test_legacy_db_compat.py 固定“缺少 cancelled 列的旧库首次打开即自动

    规则一致。

8. 行为要点汇总
--------------------------------------------------------------------------------

  - --start/--end 两个都省略：window 为 None，执行与上线前完全相同的
    目录 SELECT，保留原目录行为；--contains 语义不变，同用时名称与时段
    两个条件取交集。
  - 返回的资源在整个 [start, end) 窗口均可预约：同资源任一未取消预约与
    窗口有正时长交集即整体排除该资源。左闭右开，端点相接不阻挡；取消
    记录不占用；资源之间（含同名）独立判断；跨日窗口/预约与重复预约的
    每次发生都按完整起止日期时间逐行比较。
  - 结果顶层只有 resources；每项只有 resource_id 与 name；按标识数值
    升序（2 在 10 前）；同名不合并；无匹配返回空数组。成功退出码 0、
    stderr 为空。
  - 只提供一端、端点缺值、非法日期、格式不符、非 ASCII 时间数字、开始
    不早于结束，以及 --contains 的既有非法情形：统一输出
    {"error": "invalid_input"}，退出码 2，标准错误为空，且都在打开数据
    库之前结束——不创建文件、不迁移旧库、不改变任何数据。
  - 合法查询不改变业务记录、不消耗 AUTOINCREMENT 标识；但打开不存在的
    数据库会初始化文件，打开缺少 cancelled 列的旧库会沿用既有迁移补齐
    该列。“查询只读”指业务数据只读。
  - 所有输入时间统一按固定 UTC+08:00 解释，允许过去日期与跨日窗口；
    重复查询与重开同一文件结果一致。
  - 其他入口（resource-add、reserve、cancel、reschedule、day-query、
    free-query）的既有行为不在本文范围，保持不变。
